## エグゼクティブサマリー

LP の品質土台は良好です（外部リクエストゼロの自己完結構成・`lang="ja"`・ズーム許可・`prefers-reduced-motion` 対応など、Core Web Vitals とアクセシビリティの基礎は押さえられています）。一方で、**「公開しても集客が成立しない・法令上の不備がある」状態の残作業**と、**過去に改稿データを失った Git 運用リスク**が確認されました。

最重要は次の5点です。

1. **問い合わせ導線がゼロ** — 全6箇所の CTA の行き先であるフォームが「準備中」の無効リンクで、メール等の代替連絡先も皆無。この状態での公開・集客は流入をすべて無駄にします。
2. **特定商取引法に基づく表記が不在** — 有償サービス（月額3万円〜、構造化データでは決済手段まで宣言）を訴求しながら、事業者名・所在地・連絡先・解約条件の表示が一切ありません。
3. **公開URLプレースホルダが3ファイル7箇所に残存** — canonical / og:url / sitemap `<loc>` / robots.txt の Sitemap 行。このまま公開すると sitemap は無効、正規URLシグナルなしでインデックスされます。
4. **SNSシェア用画像が未設定** — `twitter:card=summary_large_image` を宣言しながら og:image / twitter:image が無く、シェア時に貧弱なカード表示になります。
5. **Git 運用事故の痕跡** — 2026-06-27 に約1,400行の大規模改稿版が作られた直後、上書きアップロードで**初版と完全に同一の内容へ巻き戻り**、改稿版が現行版から消失しています（コミット `188d531` に現存、復元可能）。全コミットが「Add files via upload」で意図が追跡できません。

本監査に伴い、再発防止と公開作業の漏れ防止のための **Claude Code 構成（CLAUDE.md・permissions・publish-check スキル）と README** を本ブランチで導入済みです（Phase 0 完了）。

## 2. 主要指摘の詳細（テーマ別に統合）

複数の監査次元で重複検出された指摘は統合しています（例: FAQ 不整合は SEO・構造化データ・コンテンツの3次元で独立に検出）。

### A. コンバージョン導線ゼロ 【重大・公開ブロッカー】

CTA は6箇所（ヘッダー nav・ヒーロー・サービスカード・料金カード・フッター・モバイル固定バー）すべて `#contact` に集約されていますが、到達先のボタンは `href="#"` + `aria-disabled` + `pointer-events:none` の無効状態（index.html L476）。メール・電話・SNS 等の代替連絡手段もページ全体に存在しません。
**→ フォームURL確定までは公開・集客を開始しない。間に合わない場合も最低限 mailto リンクを暫定掲載してから公開すること。**

### B. 法令・信頼性 【重大〜中】

- **特商法表記なし**（重大）: 月額3万円〜の有償サービスを訴求し、JSON-LD では「銀行振込, クレジットカード」と決済手段まで宣言しているのに、事業者名・所在地・電話・解約条件等の表示がゼロ。フォームでオンライン申込を受ける形態になれば通信販売に該当し得るため、フォーム公開と同時に必須。信頼性（B2B の成約率）にも直結。
- **プライバシーポリシー第6項が「窓口準備中」**（中）: 個人情報の取得開始（＝フォーム公開）時点で苦情申出先の記載がないと個人情報保護法上の不備になる。フォーム公開と同一リリースで解消すること。
- **実績数値・体験談の裏付け**（中）: 「11社」「144,000分」に算出根拠・集計期間の注記がなく、お客様の声は全件匿名。「…ほかにも多くの企業さまから」と件数を膨らませる表現もあり、裏付け資料がなければ景品表示法（優良誤認）リスク。根拠の注記追加と裏付け資料の社内保管を。
- **運営者名義が3通りに分裂**（中）: JSON-LD は「株式会社タイガーラボ」、ヘッダーは「生成AI導入支援」、フッター/コピーライトはキャッチコピー名義。社名の可視出現はプライバシーポリシー1箇所のみ。フッターを「© 2026 株式会社タイガーラボ」に統一し、運営者情報を明記する。
- **料金の税込/税抜が不明**（中）: 「税」の記載がページにゼロ。個人事業主も対象に含むため税込表記を明記し、ツール利用料別途・初期費用有無も注記する。

### C. 公開URL・sitemap・robots 【重大〜中・公開時に一括解消】

- プレースホルダ「あなたの公開URL」が3ファイル7箇所に残存。sitemap の `<loc>` は非ASCIIの無効URLのため、このまま Search Console に送信するとエラー。
- canonical はコメントアウト中・og:url 未記載・JSON-LD に url プロパティなし → 正規URLシグナルが皆無のままインデックスされる。
- **プロジェクトページ（`ユーザー名.github.io/リポジトリ名/`）で公開する場合、robots.txt はホストルートに置けないため Sitemap 行は機能しない**。その場合は Search Console への直接送信を正とする運用に切り替える（`.claude/skills/publish-check/SKILL.md` に手順化済み）。
- sitemap の `<lastmod>`（2026-06-13）が実際の最終更新（06-27）より古い。
- 404.html・（独自ドメイン時の）CNAME が未整備。

### D. OGP / SNS シェア 【重大】

`twitter:card=summary_large_image` を宣言しながら og:image / twitter:image が存在せず、X・Facebook・LINE・Slack でのシェア時に画像なしの貧弱なカードになります。1200×630px の OGP 画像を作成し絶対URLで指定するか、画像が用意できるまで `twitter:card` を `summary` に落とすこと。

### E. 構造化データ 【重大〜中】

- **FAQ 不整合**（重大）: JSON-LD の FAQPage は6問だが、ページ可視 FAQ は5問。「途中で解約はできますか？」が本文に存在せず、Google の「マークアップ内容はページ上で見えること」というガイドラインに違反。ヒーローで「長期契約の縛りなし」と訴求している内容でもあるため、**本文 FAQ に解約の Q&A を1件追加して一致させるのが最善**。（参考: 2023年8月以降 FAQ リッチリザルト表示は政府・医療系にほぼ限定のため実利は限定的だが、ガイドライン違反状態は解消すべき）
- **ProfessionalService に address がなくリッチリザルト対象外**（中）: ProfessionalService は LocalBusiness 系で address が必須。住所非公開方針なら `@type` を `Organization`（または `OnlineBusiness`）に変更し、name / url / logo / contactPoint 中心の構成にするのが安全。
- paymentAccepted（銀行振込・クレジットカード）が本文のどこにも記載なし。alternateName のキャッチコピーは `slogan` プロパティが適切。priceRange「¥30,000〜」は月額であることが欠落。

### F. アクセシビリティ 【重大〜中】

- **FAQ アコーディオンがキーボード・スクリーンリーダーで操作不能**（重大）: `.faq-q` が div + click のみで、tabindex / keydown / aria-expanded が一切ない。`<details><summary>` への置換が最小工数で確実（JS 不要になり、下記の JS 無効問題も同時に軽減）。
- **JS 無効/失敗時に主要コンテンツが非表示**（中）: `.reveal` の初期状態が `opacity:0` で、表示は JS（IntersectionObserver）頼み。`<noscript><style>.reveal{opacity:1;transform:none}</style></noscript>` の追加、または「JS 実行時のみ非表示にする」方式への変更を。
- **ヒーローの白文字がコントラスト不足**（中）: グラデーション明部（#7fb3f5）上の `opacity:.85〜.95` テキストや ghost ボタンが WCAG AA 未達。グラデーション終端を暗めに、opacity を外す。
- **900px 以下で nav が消え代替なし**（中）: モバイルでセクションへの導線が固定CTA以外なくなる。開閉式メニュー（details/summary でも可）を。
- 準備中 CTA が `<a href="#">` のままタブ到達可能（中）→ `<span>` か `<button disabled>` に。
- main ランドマーク/スキップリンクなし、見出し階層の飛び（プロフィールに h2 なし）、装飾絵文字・引用符に aria-hidden なし、`scroll-behavior:smooth` が reduced-motion で無効化されない（低）。

### G. リポジトリ運用 【重大〜中】

- **上書きアップロードによる改稿消失**（重大・経緯は §1）: 再発防止として (1) main のブランチ保護（直 push 禁止・PR 必須）、(2) Web UI の「Add files via upload」による丸ごと上書き運用の廃止、(3) 差分ベースの編集（Claude Code / git CLI）への移行。
- コミットメッセージ全件が Web UI 既定文言（中）→ 変更内容が分かる日本語メッセージを規約化（CLAUDE.md に明記済み）。
- CI 不在（中）→ HTML 検証・プレースホルダ残存検知・リンクチェックの GitHub Actions（30行程度）を公開後に導入推奨。
- README 不在（中）→ 本ブランチで導入済み。公開手順がファイル内コメント3箇所に散在していた問題を README + publish-check スキルに集約。

### H. 低優先の改善（抜粋）

title 約38文字で SERP 末尾切れの可能性（主要キーワードは前方配置済みで致命的ではない）／meta description 約101文字でモバイル末尾切れ／favicon の PNG/apple-touch-icon フォールバックなし／HTML 未ミニファイ（37KB・実害小）／インライン style 12箇所の散在／backdrop-filter の -webkit- プレフィックス欠落／meta keywords は無効（削除可）。

### 問題なしと確認された点（参考）

外部リクエストゼロの自己完結構成（表示速度の土台として優秀・現状維持推奨）／`lang="ja"`／ズーム禁止なし／装飾 SVG への aria-hidden／`prefers-reduced-motion` 対応（reveal アニメーション）／robots.txt のクロール許可設定自体は正しい。

## 4. 段階的実行プラン

### Phase 0: Claude Code 構成の導入 — ✅ 本ブランチで完了
- `CLAUDE.md`（編集時の不変条件・Git 規約・事故の教訓）
- `.claude/settings.json`（読み取り系コマンドの最小 allow）
- `.claude/skills/publish-check/SKILL.md`（公開時の一括差し替え手順）
- `README.md`（公開前チェックリストの集約）・本レポート

### Phase 1: 公開前のコンテンツ修正（URL 確定を待たずに着手可能）
上記マトリクスの ①〜⑤・⑩〜⑫。すべて index.html の差分編集で完結し、破壊的操作なし。
順序の推奨: FAQ 同期 → 社名統一 → 税表記 → a11y 修正（details/summary 化・noscript・CTA 要素変更）→ JSON-LD 型変更。各修正後に `sitemap.xml` の lastmod を更新。

### Phase 2: 公開リリース（URL・フォーム確定後）
1. 公開URL確定（プロジェクトページか独自ドメインかで robots.txt の扱いが変わる点に注意）
2. `/publish-check` スキルを実行して URL 5点セットを一括差し替え・残存ゼロを grep 確認
3. フォーム有効化・プライバシー窓口記載・特商法表記を**同一リリース**で反映
4. OGP 画像を追加（間に合わなければ twitter:card を summary に一時変更）
5. 公開後: Search Console へ sitemap 送信、OGP/リッチリザルト検証、`v1.0` タグ

### Phase 3: 運用の堅牢化（公開後）
- GitHub で main のブランチ保護を有効化（Settings → Branches。直 push 禁止・PR 必須）
- GitHub Actions で HTML 検証 + プレースホルダ/無効リンク検知の CI を追加
- 失われた改稿版（`188d531`）の要否を判断（必要なら復元して差分を取り込む）

**破壊的操作の注意**: 本プランに削除・移動系の操作は含まれません。唯一の非可逆操作は「main へのマージ」であり、必ず PR レビューを経てください。ブランチ保護の設定はコード変更より先に行っても安全です。

## 6. 今回導入した Claude Code 構成の設計意図

**振り分け原則: 常時必要＝CLAUDE.md／手続き＝skill／強制したい＝permissions／今回は hook・subagent は不採用**

- **CLAUDE.md**: このリポジトリ最大のリスク3点 —「意図的なプレースホルダを AI が勝手に埋める」「JSON-LD と本文の不整合の再発」「丸ごと上書きによる消失の再発」— を不変条件として明記。個別の修正項目（コントラスト等）は毎回必要な知識ではないため意図的に載せず、約40行に抑えた。
- **.claude/settings.json**: 頻出する読み取り系コマンド（git log/diff/show・grep・ls 等）のみ許可し、確認プロンプトを削減。書き込み系は通常の承認フローに残す（非エンジニアオーナーには安全側が適切）。deny・hooks は不採用 — HTML 1枚の規模では壊れた hook がオーナーを混乱させるリスクの方が大きい。
- **publish-check スキル**: 公開URL確定時の「4ファイル横断・7箇所・1回きりだが絶対に漏らせない」差し替え作業は、重大指摘の大半が集約される瞬間。長い手順＋条件分岐（プロジェクトページか独自ドメインか）を含むため、CLAUDE.md ではなくスキルに配置。「公開前チェックして」「URLが決まった」で発火する。
- **README.md**: 3ファイルのコメントに散在していた公開手順を1箇所のチェックリストに集約。
