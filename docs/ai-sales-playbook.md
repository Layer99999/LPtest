# 生成AI提案 必勝パターン体系（セグメント別プレイブック）

> 株式会社タイガーラボ ／ 中小企業向け生成AI導入支援サービス
> 「企業属性 × 刺さるプレゼン」を体系化した社内向け営業設計ドキュメント
> 最終更新：2026-06

---

## 第0部　全体設計思想（最初に必ず読む）

### 0-1. 核心原則：表層属性は「束ね」にすぎない

「規模」や「業種」は、相手の本質を直接表すものではなく、**より深い3つの本質軸を束ねた“ラベル”**です。
例えば「飲食店」という業種ラベルは、実態としては「①意思決定がオーナー1人で速い」「②人手不足が最大の痛み」「③ITリテラシーが低め」という3つの本質をまとめて表現しているにすぎません。

したがって、提案設計は **表層属性 → 本質3軸 → プレゼン設計** という順で考えます。

| 本質軸 | 問い | プレゼンへの影響 |
|---|---|---|
| **① 意思決定構造** | 誰が・何人で・何を基準に決めるか | 「誰に話すか」「資料の重さ」「決裁プロセスの設計」 |
| **② 経営課題タイプ** | 一番の痛みは何か（守り/攻め） | 「何を訴求するか」「どの数字を見せるか」 |
| **③ AIリテラシー／DX成熟度** | どこまで分かっているか | 「どう見せるか」「専門用語の量」「デモの粒度」 |

### 0-2. すべての提案を貫く3層構造

どんな相手でも、提案は必ずこの3層で組み立てます。

```
WHO   誰に話すか      → 意思決定構造に合わせる（決裁者か現場か、単独か合議か）
WHAT  何を訴求するか   → 経営課題に合わせる（コスト削減か売上拡大か属人化解消か）
HOW   どう見せるか     → AIリテラシーに合わせる（数字か、デモか、ビジョンか）
```

### 0-3. 生成AI提案の「黄金律」5箇条

1. **AIの話をしない。** 相手の課題と、その課題が解けた後の世界を話す。AIは手段。
2. **「導入」をゴールにしない。** 「定着して数字が変わる」ところまでを約束する（タイガーラボの研修・伴走が差別化点）。
3. **最初の一撃は“相手の業務の具体例”。** 一般論のChatGPTデモは響かない。相手の見積書・問診票・予約対応で見せる。
4. **金額より先に“回収”を見せる。** 月3万円ではなく「月◯時間＝◯円の削減」を先に置く。
5. **意思決定者の数だけ資料を変える。** 1人決裁ならデモ1本、合議制なら「稟議が通る紙」を作る。

## 第1部　セグメンテーションの軸（切り口の全体整理）

ご相談の「①事業規模 ②事業領域」に、提案設計上クリティカルな軸を加えて、合計6軸で整理します。
①②は**表層軸（相手を分類するため）**、③〜⑥は**本質軸（プレゼンを設計するため）**です。

| # | 切り口 | 主な区分 | 役割 |
|---|---|---|---|
| ① | **事業規模** | 大企業 / 中堅 / 中小 / ベンチャー / 大型個人事業主 | 表層・入口 |
| ② | **事業領域（業種）** | B2C（飲食・塾・美容…）/ B2B（建設・IT・町工場…） | 表層・入口 |
| ③ | **意思決定構造** | 単独決裁 / 少数合議 / 多層稟議 | 本質・WHO |
| ④ | **経営課題タイプ** | 守り（人手不足・コスト・属人化）/ 攻め（売上・新規・ブランド） | 本質・WHAT |
| ⑤ | **AIリテラシー／DX成熟度** | 無関心 / 興味あり未着手 / 試行中 / 活用中 | 本質・HOW |
| ⑥ | **導入動機（トリガー）** | 危機回避 / 競合追随 / 成長投資 / 経営者の興味 | 本質・温度感 |

> 提案準備の手順：**①②で当たりをつけ → ③④⑤⑥でヒアリングして確定 → 第2〜4部の型を選ぶ。**

## 第2部　事業規模別 必勝パターン

### 2-1. 大企業（従業員300名〜）

| 項目 | 内容 |
|---|---|
| **意思決定** | 多層稟議・合議制。情シス／法務／経営企画が関与。決裁が遅く、関係者が多い。 |
| **本当の関心** | 全社展開・ガバナンス・セキュリティ・実績（他社事例）・失敗できないこと |
| **刺さるメッセージ** | 「まず一部門でPoC（小さく実証）→ 成果を数字で示して全社展開」 |
| **見せ方** | 体系的な資料・導入ロードマップ・セキュリティ／情報漏洩対策・ROI試算・他社事例 |
| **訴求軸** | リスク低減 ＋ 全社の生産性指標（守りと標準化） |
| **避けること** | 「とりあえずChatGPT入れましょう」的な軽さ。担当者の独断で決まると思うこと。 |
| **タイガーラボの立ち位置** | 大手コンサルより安価・小回り・現場密着の「PoC伴走パートナー」。※規模的に本命ではないが、一部門・子会社・地方拠点単位なら十分射程内。 |
| **想定反論→切り返し** | 「社内に専任部署がある」→「専任部署の“現場展開・研修”の手が足りていないのでは。我々は実装と定着の実働部隊として補完できます」 |

### 2-2. 中堅企業（従業員50〜300名）

| 項目 | 内容 |
|---|---|
| **意思決定** | 少数合議。社長＋役員数名。比較的速いが、社内調整は残る。 |
| **本当の関心** | 部門横断の効率化、人材採用難の補完、属人化からの脱却 |
| **刺さるメッセージ** | 「採用1名分のコストで、複数部門の残業を恒常的に削減できる」 |
| **見せ方** | 部門別の業務棚卸し → 効果の大きい順にロードマップ。3〜6ヶ月の段階導入。 |
| **訴求軸** | 人件費・採用難の解決（守り）＋ 競合との差（攻め） |
| **避けること** | 1部門だけの小ネタで終わること。横展開の絵を必ず描く。 |
| **タイガーラボの立ち位置** | **最有力ゾーン。** 専任部署はないが投資余力はある。伴走型がハマる。 |

### 2-3. 中小企業（従業員〜50名）★コアターゲット

| 項目 | 内容 |
|---|---|
| **意思決定** | 社長単独 or 社長＋右腕。**即決可能。** これが最大の武器。 |
| **本当の関心** | 目の前の人手不足・社長自身の作業時間・「うちにもできるのか」という不安 |
| **刺さるメッセージ** | 「社長が毎日やっているその作業、今日から半分にできます」 |
| **見せ方** | **その場で、相手の実業務でデモ。** 見積・メール・SNS投稿文・議事録など。 |
| **訴求軸** | 社長個人の時間 → 会社のコスト（守り中心、超具体） |
| **避けること** | 抽象論・横文字・大層なロードマップ。**重い資料は逆効果。** |
| **価格の見せ方** | 「月3万円＝1日1,000円。社長の1日1時間が戻れば余裕で元が取れる」 |
| **想定反論→切り返し** | 「うちは小さいから関係ない」→「小さいからこそ社長1人の時間が会社の生命線。大企業より効果が直撃します」 |

### 2-4. ベンチャー／スタートアップ

| 項目 | 内容 |
|---|---|
| **意思決定** | 創業者単独・即決。スピードと費用対効果に極端に敏感。 |
| **本当の関心** | 少人数で売上を伸ばす／非エンジニア業務の自動化／資金を使わず成長 |
| **刺さるメッセージ** | 「人を増やさずにスケールする。生成AIは“最初の10人目の社員”」 |
| **見せ方** | スピード感のあるデモ、最新ツール、すぐ試せる小さな勝ち筋 |
| **訴求軸** | 成長・レバレッジ（攻め） |
| **避けること** | 古い・重い・お役所的な提案。リテラシーが高いので**初歩的すぎると見限られる**。 |
| **注意** | 自前で出来てしまう層。**価値は「実装代行」より「最適なツール選定・設計・時間の節約」**で売る。 |

### 2-5. 規模の大きな個人事業主（士業・コンサル・クリエイター・店舗オーナー複数店等）

| 項目 | 内容 |
|---|---|
| **意思決定** | 本人単独・即決。ただし**財布も本人**＝費用対効果に超シビア。 |
| **本当の関心** | 自分の作業時間＝そのまま売上機会。1人で複数の役割を回す負荷。 |
| **刺さるメッセージ** | 「あなたの“事務作業の時間”を、本業（稼ぐ時間）に丸ごと振り替える」 |
| **見せ方** | 本人の実作業（提案書作成・SNS・経理・顧客対応）を1つ、その場で自動化して見せる |
| **訴求軸** | 時間＝お金（守り＝事務削減 ／ 攻め＝集客・発信の量産） |
| **避けること** | 「社員研修」「全社展開」など組織前提の話。1人事業の文脈に翻訳する。 |
| **タイガーラボの立ち位置** | 月額が軽いので刺さりやすい。**“デジタル秘書を雇う感覚”**で提案。 |

## 第3部　業種別 必勝パターン

> 業種は「①典型的な痛み ②刺さるユースケース ③デモの題材」をセットで覚える。
> 提案の冒頭は必ず**「御社の◯◯（具体業務）、今こうされてますよね？」**から入る。

### 3-A. B2C（消費者向け）

B2C共通の傾向：**現場が忙しく・ITが苦手・社長＝現場プレイヤー・即決・効果は集客と接客と事務に出る。**

| 業種 | 典型的な痛み | 刺さるユースケース（デモ題材） | キラーメッセージ |
|---|---|---|---|
| **飲食店** | 人手不足、予約・問合せ対応、SNS発信が続かない | 予約/問合せ自動応答、メニュー・SNS投稿文の量産、口コミ返信、多言語POP | 「忙しい時間の電話対応とSNS、AIに任せて料理に集中」 |
| **学習塾・教育** | 保護者対応、教材・問題作成、面談準備、講師の属人化 | 保護者向け連絡文・面談記録の自動作成、教材/小テスト生成、進路相談の下書き | 「先生が“教える”以外の事務を全部巻き取る」 |
| **美容室・サロン** | 予約管理、リピート促進、SNS集客、指名の属人化 | 予約・キャンセル対応、来店後フォローLINE文、スタイル提案文、SNSネタ出し | 「席に座る前から、AIが集客とフォローを回す」 |
| **小売・EC** | 商品説明文、問合せ、在庫・レビュー対応 | 商品説明/LP文の量産、問合せ自動応答、レビュー要約・返信 | 「商品ページ作成の作業時間を1/5に」 |
| **クリニック・治療院** | 受付・予約、問診、説明文書、口コミ対応 | 問診票の要約、予約・問合せ応答、患者向け説明文・注意書きの作成 | 「受付と書類仕事を減らし、患者と向き合う時間を増やす」 |

**B2C提案の鉄則**：難しい話は一切しない。「スマホで」「今日から」「この作業が」の3点セット。デモは必ずその店の実物（メニュー、生徒、メニュー表）で。

### 3-B. B2B（事業者向け）

B2B共通の傾向：**意思決定がやや複雑・効果は見積/書類/技術継承に出る・「品質」と「信頼」を重視・派手さより堅実さ。**

| 業種 | 典型的な痛み | 刺さるユースケース（デモ題材） | キラーメッセージ |
|---|---|---|---|
| **建設業** | 見積・積算、書類（施工計画/安全書類）、職人の高齢化・技術継承、写真整理 | 見積/書類のドラフト自動生成、議事録、過去図面・仕様の検索Q&A、安全書類作成 | 「ベテランの段取りと書類仕事を、AIに引き継ぐ」 |
| **製造業・町工場** | 属人化、技術伝承、規格・マニュアル整備、問合せ対応 | 作業手順書/マニュアル生成、不具合事例の検索、見積回答、英文メール | 「ベテランの頭の中を、誰でも引き出せる仕組みに」 |
| **IT・Web制作** | リソース逼迫、提案書・仕様書、コード補助、ドキュメント | 提案書/仕様書ドラフト、コード生成補助、テスト、議事録、保守問合せ対応 | 「同じ人数で受けられる案件量を増やす」 |
| **士業（税理士・社労士等）** | 顧問先対応、書類作成、法改正キャッチアップ、属人化 | 顧客向け文書・メール、制度調査の要約、申請書ドラフト、FAQ対応 | 「先生1人あたりの顧問先数を増やす武器」 |
| **卸・物流・商社** | 受発注・問合せ対応、データ入力、多言語、ドキュメント | 問合せ自動応答、受発注メール処理、商品データ整備、翻訳 | 「定型の受発注・問合せを24時間AIが捌く」 |

**B2B提案の鉄則**：派手さより「品質と継続」。**技術継承・属人化解消**は中小B2Bの最強フック。見積・書類の“ドラフト自動化”は数字で語りやすく、決裁が通りやすい。

## 第4部　意思決定 × リテラシー マトリクス（プレゼンの型を決める核心）

ここが**プレゼンの「型」を最終決定する**最重要パートです。WHO（縦：誰が決めるか）× HOW（横：どこまで分かっているか）で4象限。

```
                 リテラシー：低い              リテラシー：高い
              （無関心〜興味のみ）          （試行中〜活用中）
          ┌──────────────────────────┬──────────────────────────┐
 決裁：   │ ① 体感デモ即決型           │ ② 設計パートナー型         │
 単独     │ 中小・個人・店舗オーナー    │ ベンチャー・IT・若手社長    │
（速い）  │ → その場デモ1本で即クロージング│ → 一般論禁止。ツール選定/    │
          │   不安払拭が9割             │   設計/最新動向で対等に組む  │
          ├──────────────────────────┼──────────────────────────┤
 決裁：   │ ③ 稟議支援型               │ ④ PoC実証型                │
 合議     │ 中堅・地方の老舗B2B         │ 大企業・先進的中堅          │
（遅い）  │ → “社内を説得する紙”を渡す   │ → 小さく実証→数字→横展開    │
          │   推進担当者を主役にする     │   ガバナンス/セキュリティ重視 │
          └──────────────────────────┴──────────────────────────┘
```

### 各象限の必勝アクション

| 象限 | プレゼンの主役 | 必勝アクション | 渡す成果物 |
|---|---|---|---|
| **① 体感デモ即決型** | 社長本人の驚き | その場で相手の実業務をAIで処理して見せる。理屈より体感。 | 即・無料相談 → 簡単な導入プラン1枚 |
| **② 設計パートナー型** | 相手の知的好奇心 | 最新ツール比較・設計思想で対等に。代行ではなく「時間と最適解」を売る。 | ツール選定マップ・構成図 |
| **③ 稟議支援型** | 社内の推進担当者 | 担当者が上司を説得できる資料（費用対効果・他社事例・リスク低減）を作る。 | 稟議用ROI試算・1枚サマリ |
| **④ PoC実証型** | 経営の意思決定会議 | 小さく実証→数字で証明→全社展開のロードマップ。セキュリティ前提。 | PoC計画書・効果測定レポート |

## 第5部　共通フレーム（どの相手にも使う武器）

### 5-1. 初回面談の黄金フロー（タイガーラボ標準）

```
1. ヒアリング（課題と業務の具体化）   … 「一番時間を取られている作業は？」
2. その場デモ（相手の実業務で1つ）    … “体感”を作る。ここが勝負の8割。
3. 効果の可視化（時間→コスト換算）     … 「月◯時間＝◯円」
4. 導入イメージ（軽い1枚プラン）       … 重くしない。次の一歩だけ示す。
5. 価格（回収を見せてから提示）        … 月3万円＝1日1,000円。
6. クロージング（小さく始める提案）     … 初回相談無料・1業務から。
```

### 5-2. 経営課題タイプ別の「訴求テンプレ」

| 課題タイプ | 訴求の言い回し | 見せる数字 |
|---|---|---|
| 人手不足 | 「採用せずに、人を増やしたのと同じ効果」 | 削減時間 ÷ 人件費 |
| コスト削減 | 「固定費を増やさず、業務量を増やす」 | 月◯時間 × 時給 |
| 属人化・技術継承 | 「あの人にしか出来ない仕事を、仕組みに変える」 | 引継ぎ工数・離職リスク |
| 売上拡大（攻め） | 「発信・提案・接客の“量”を10倍に」 | 投稿数・提案数・対応件数 |
| 社長の時間 | 「経営者が経営に集中できる時間を作る」 | 社長の作業時間 |

### 5-3. よくある反論と切り返し（共通）

| 反論 | 切り返しの軸 |
|---|---|
| 「ウチの業界は特殊だから無理」 | 業界特化のユースケースを即提示。特殊な業務ほど属人化していて効果が大きい。 |
| 「情報漏洩・セキュリティが不安」 | 法人向けプラン／学習させない設定／社内ルール設計まで支援することを明示。 |
| 「自分でChatGPT触ったけど使えなかった」 | 「使い方の設計」が抜けていただけ。業務に合わせた“型”を作るのが我々の仕事。 |
| 「高いのでは？」 | 月3万円＝1日1,000円。削減される時間のコストと比較すれば投資対効果は明確。 |
| 「今は忙しい／落ち着いたら」 | 忙しいからこそ効く。落ち着く頃には競合が先行している。1業務だけ今すぐ。 |

### 5-4. 価格・プランの見せ方（月額3万円〜・初回相談無料を活かす）

- **必ず「回収」を先に置く。** 金額は時間削減の換算の“後”に出す。
- **入口は1業務に絞る。** フルパッケージで怯ませない。「まずこの作業だけ」。
- **無料相談を“診断”として価値化。** 「無料で業務の棚卸しと改善ポイントを出します」。

## 第6部　クイックリファレンス早見表

相手が分かったら、この表で一発で「型」を引く。

| もし相手が… | WHO（誰に） | WHAT（訴求） | HOW（見せ方） | 一言メッセージ |
|---|---|---|---|---|
| **中小・店舗オーナー** | 社長本人 | 社長の時間・人手不足 | その場デモ・超具体 | 「その作業、今日から半分に」 |
| **大型個人事業主** | 本人 | 時間＝売上 | 実作業を1つ自動化 | 「事務をAI秘書に丸投げ」 |
| **中堅企業** | 社長＋役員 | 採用難・横展開 | 業務棚卸し→段階導入 | 「採用1名分で全部門の残業を削減」 |

| **ベンチャー/IT** | 創業者 | 成長レバレッジ | 最新ツール・対等な設計 | 「人を増やさずスケール」 |

### 付録：この体系の使い方（運用メモ）

1. 商談前：**①②（規模・業種）**で当たりをつけ、想定の型を1つ仮置きする。
2. 商談序盤：**③④⑤⑥**をヒアリングで確定（特に「誰が決めるか」「一番の痛み」「触ったことあるか」）。
3. 商談中盤：第4部マトリクスで**最終的な型**を確定し、デモと数字を出す。
4. 商談終盤：第5部の共通フレームでクロージング。
5. 商談後：実際に刺さった/外したパターンをこのドキュメントに追記し、社内資産として育てる。

> このプレイブックは「完成品」ではなく「育てる土台」です。商談ごとの実データ（どの業種に何が刺さったか）を追記し、必勝パターンの精度を上げ続けてください。
